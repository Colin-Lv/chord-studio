# 分轨融合和声：实现与**负结果**记录

日期：2026-11-01。目标：用音轨分离（只保留演奏和弦的声部）去提高和弦识别精度。
本轮只看和弦，不看主调。文献扫描见 [RESEARCH.md](RESEARCH.md)，全部数字都是本机实测。

## 1. 结论先行

**在当前冻结模型上，分轨融合没有提高和弦识别精度，反而降低。**

在唯一有用户确认金标准的歌（《虚拟》，62 段、229 秒）上，全部走 App 自己的
完整段解码器（`retained10_full` 同款），只改「喂给解码器的后验」：

| 输入 | 帧级准确率 | 根音 | 段级（参考段内多数） |
|---|---:|---:|---:|
| 整首混音（基线） | **68.13%** | **87.55%** | **69.35%** |
| 混音 + 和声轨后验 λ=0.15 | 66.20% | 85.94% | 67.74% |
| λ=0.25 / 0.35 | 66.20% | 85.94% | 67.74% |
| λ=0.50 | 64.27% | 84.01% | 66.13% |
| λ=0.65 | 62.96% | 83.08% | 66.13% |
| 只用和声轨（λ=1.0，原始格解码） | 34.32% | 63.67% | 43.55% |

规律很清楚：**和声轨的权重越大，结果越差**，最优是 λ=0（即不改）。
低音先验 β 也试过（0.2 / 0.5 / 1.0），在原始格解码上全部中性或更差。

## 2. 关键教训：换解码器会改写结论

第一版原型在 0.25 s 原始格上做 argmax 再对比金标准，得到「融合 +4.8 个点」。
把同一个后验交给 App 的完整段解码器（小节相位 + 边界分类 + 半马尔可夫）后，
基线从 40.3% 抬到 68.1%，融合的相对优势直接翻负。

原因有两个，都是评测口径问题：

1. **基线选错**：App 发布的默认时间轴不是原始格 argmax，而是完整段解码。拿原始格
   融合结果去比完整段基线，等于用弱基线衬托自己。
2. **指标错**：金标准是 62 个「段」，原始格有 985 个 0.25 s 格。帧级对比会同时惩罚
   边界抖动和质量判断，段级多数投票又会掩盖过度分割。

这条与文献扫描的警告一致（RESEARCH.md §8.5）：任何「stems → 和弦」的增益声明，
必须固定解码器、固定指标，并且同时报基线。

## 3. 文献怎么说的

| 研究 | 做法 | 真实数据上的增益 |
|---|---|---|
| Mitoma & Furuya, APSIPA 2025 | HTDemucs 四轨按轨增益重混后喂预训练 BTC | triads WCSR **+0.20 点**（75.52→75.72），485 首真实曲目；单轨消融全部变差 |
| Sumi et al., ISMIR 2008 | bass pitch probability 做模型内概率融合 | 帧级 +8.1 点，但那是「假设搜索内部」的融合，不是换输入 |
| Jointist / Cerberus | 联合训练分离与和弦 | MajMin 0.798→0.812，需要训练，且用的是符号 piano roll |

也就是说：**换输入这条路的上限本来就只有零点几个点**，而且增益来自相对电平重排，
不是「分离得更干净」。我们测到负值，量级上并不意外。

## 4. 这一轮实际交付了什么

### 4.1 新识别流程（`fusion_engine.py`）

```
分轨（六轨精细） → 和声混音 H = bass + other + guitar + piano（响度对齐到全混音）
   → 冻结前端在 H 上再跑一次，得到第二份 120 类后验
   → 与混音后验做对数线性融合（λ）+ 可选低音根音先验（β）
   → 交给 App 的完整段解码器（与 retained10_full 同一套）
   → 作为新来源 stem_fusion 写回 analysis.json（附 .lab 与 sha256）
```

- 和声轨推理走 `inference_windowless.py`，与主分析同一条链路，结果按音频哈希缓存
- 融合来源与其它来源同构（name / path / sha256 / bytes / rows），可被修正、导出、播放
- 不做默认替换：`harmony_default` 默认关闭

### 4.2 一次设置好的完整流程（`pipeline_worker.py`）

工作台「音轨分离」按钮现在打开的是**完整流程面板**，一次勾选：

- 分轨模型（标准 / 精细 / 人声优先 / 六轨精细）
- 人声细分（主唱 / 和声）、吉他细分（木电 / 旋律伴奏）、鼓组细分（六件）
- 同时识别和声（分轨融合·实验）、是否设为默认时间轴

提交后按 `和声分析 → 音轨分离 → 人声细分 → 吉他细分 → 鼓组细分 → 分轨融合`
顺序执行，进度标签带 `n/N`，完成后直接打开结果。实测（《虚拟》，全部缓存命中）44 秒；
含鼓组细分 100 秒；冷启动首次约 5 分钟。

不再需要「先跑四轨、再点六轨、再点人声细分」这样一步步来。

## 6. 边界与后续

- 只有一首歌有金标准；结论不能外推到所有曲目，但方向与文献一致（增益上界很小）。
- 没有试「保留鼓」的 Mitoma 配置，也没有试 stem 增益扫描（文献说是电平重排带来的）。
- 真正可能有用的方向不是「换输入」，而是**把分离出的低音/钢琴作为额外特征喂进训练**
  ——那需要重新训练，超出本轮范围。
- 产品上保留这个开关，标为实验、默认关闭；如果将来换到更强的和弦模型（能吞 chroma
  或多通道输入），这条流程可以直接复用。
