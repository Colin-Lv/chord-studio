# 人声细分结果展示与切换修复

日期：2026-11-01

## 实际输入与问题原因

`vocal_parts_worker.execute` 将当前模型目录下的 `wav/vocals.wav` 传给细分模型；输入是已经提取的人声轨。标准、精细、人声优先、六轨精细各有自己的父人声与子轨结果，不能把某版子轨静默混入另一版伴奏。

旧界面每次切换只加载当前模型的子轨结果，没有跨版本的结果入口；任务完成时，仅在当前所选模型与任务来源相同时才展示。刷新也不会恢复进度。它们共同导致结果像被重置、完成后难以找到。实际检查确认《虚拟》的标准、精细、六轨精细三版缓存均可读取，不是这三版文件被删除。

## 修改

- 添加常驻“主唱与和声”区域，标明来源、保存状态、试听和下载位置。
- 列出各已生成版本的有效细分结果；“查看结果”切到对应父版本并展开，保持音轨来源一致。
- 已有结果默认展开；用户主动收起的选择按项目、版本记住。选定版本同时写入页面地址，刷新恢复。
- 任务跟踪独立于所选版本；从服务器 active_job 和本地任务记录恢复。任务在别的版本完成仍更新入口和通知。
- 区分读取异常与结果不存在，网络短暂中断时继续查询任务。
- 防止快速切换的旧请求覆盖新选择；防止旧细分查询覆盖新结果。
- 修复每次切换重复绑定键盘监听的问题；音轨名称增加完整悬停提示。

只修改前端 `stems.js`、`stems.html`、`stems.css`。未修改推理器、缓存校验或已生成音频。

## 验证

- `check_flow.py`：10 组浏览器场景通过，包括已有结果展示、跨版本找回、收起记忆、运行中切换及刷新、完成后来源一致、服务器任务恢复与失败、快速切换竞态、读取失败、独奏和下载、真实《虚拟》缓存读取。模拟任务不调用实际模型。
- `tests/test_vocal_parts.py` 和 `tests/test_studio_controls.py`：20 passed，1 项既有依赖弃用警告。
- 已同步三个前端文件到桌面安装目录，覆盖前备份在 `installed_before`。
- 对当前桌面服务检查：实际返回的 JS/CSS 与工作区哈希一致；三个已保存版本入口可见；标准切换精细、刷新、子轨展开均通过，浏览器无脚本错误。详见 `installed_check.json`。

当前已打开的旧页面需要刷新或重新进入分轨页，后台任务无需重启。父人声如果被重新生成且内容变化，旧子轨仍会依照现有校验判为不可用；本次没有绕过这一来源一致性检查。
