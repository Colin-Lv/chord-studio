# 换输入实验：原曲 vs 伴奏+贝斯 vs 仅伴奏（同一套 v90 权重）

日期：2026-11-01。目的：不改模型、不改解码器，只把**喂给 v90 的音频**换成分轨结果，
看和弦识别是否提高。评测材料是唯一有用户确认金标准的《虚拟》（62 段、1.8–230.7 s）。

## 1. 三种输入怎么做的

| 条件 | 组成 | 说明 |
|---|---|---|
| A 原曲 | 项目原始音频解码为 44.1 kHz 立体声 wav | 基线，与 App 发布的时间轴同源 |
| B 伴奏+贝斯 | other + guitar + piano + **bass** | 用户建议的首选实验 |
| C 仅伴奏 | other + guitar + piano | 去掉贝斯，检验贝斯是帮忙还是干扰 |
| D 去人声（诊断） | drums + bass + other + guitar + piano | 只去掉人声，用来分离「去人声」与「去鼓」的贡献 |

每条轨等增益相加，不逐轨归一化；另做 B/C 的**整体响度对齐**版本（对齐到 A 的 RMS），
确认结论不是音量差造成的。三种输入都走同一条冻结前端（`inference_windowless.py`），
再用 App 自己的完整段解码器（与 `retained10_full` 同一套）解码，节拍网格沿用原曲。

## 2. 时间区间内的和弦标签对比

| 条件 | 帧级准确率 | 根音 | 相对 A |
|---|---:|---:|---:|
| **A 原曲** | **68.34%** | **87.55%** | — |
| B 伴奏+贝斯 | 62.99% | 85.59% | **−5.35 / −1.96** |
| B 响度对齐 | 62.99% | 85.59% | 与 B 完全相同 |
| C 仅伴奏 | 68.23% | 81.00% | −0.11 / **−6.55** |
| C 响度对齐 | 67.79% | 82.10% | −0.55 / −5.45 |
| D 去人声 | 64.63% | 83.19% | −3.71 / −4.36 |

**没有任何一种替换超过原曲。** 响度对齐后 B 一分不差、C 只差 0.4，
说明差异不是音量造成的。

## 3. 完整自动分段结果

| 条件 | 段数 | 段级准确率 | 边界 P | 边界 R | 边界 F1 |
|---|---:|---:|---:|---:|---:|
| A 原曲 | 62 | 69.35% | 90.32% | 90.32% | 90.32% |
| B 伴奏+贝斯 | 65 | 66.13% | 90.77% | 95.16% | **92.91%** |
| C 仅伴奏 | 66 | **70.97%** | 87.88% | 93.55% | 90.62% |
| D 去人声 | 64 | 64.52% | 92.19% | 95.16% | **93.65%** |

- 段级上 C 比 A 高 1.6 个百分点，但**多出 4 段**（66 vs 62），属于轻度过分割；
- B 和 D 的**边界 F1 更高**（92.9 / 93.7），但和弦标签更差——分离改善了「换和弦的位置」，
  没有改善「换成了什么和弦」；
- 边界提升同时伴随段数增加，说明提升的一部分来自多提候选边界，不能单独当作收益。

## 4. 逐段拆解：改对了什么、改错了什么

以 A 为基准，按金标准 62 段逐段比较：

| 条件 | 改对 | 改错 | 都对 | 都错 |
|---|---:|---:|---:|---:|
| B 伴奏+贝斯 | 2 | 4 | 39 | 17 |
| C 仅伴奏 | **4** | 3 | 40 | 15 |
| D 去人声 | 1 | 4 | 39 | 18 |

C 改对的例子都是**和弦性质**：`E:7 → E:min7`、`F:maj9 → F:maj7`、`F:maj → F:maj7`，
即伴奏里三音/七音更清楚时的典型修正。批错的则集中在根音。

## 5. 结论

1. **换输入这条路在当前 v90 上不成立**：最好也只是打平（C：帧级 −0.1），
   其余条件明显更差。
2. **贝斯的作用是分裂的**：去掉贝斯，根音准确率从 87.55% 掉到 81.00%（−6.55）；
   把贝斯加回伴奏，根音回到 85.59，但帧级掉到 62.99（−5.35）。
   → 贝斯是**根音证据**，不是完整的和弦证据；把它整轨混进输入会同时放大低音的
   持续音与经过音，覆盖掉伴奏给出的性质信息。
3. 这恰好支持你们 V2 的架构：**伴奏出性质、贝斯出根音、两者分开打分**，
   而不是混成一条音频再喂模型。纯换输入做不到这个分离。
4. **去人声本身就有代价**（D：−3.71），说明当前模型依赖人声里的谐波线索；
   「先去掉人声再识别」不是免费的。

## 6. 局限

- 只有一首带金标准的歌，1.6 个百分点的差别只相当于 1 段，不能当显著结果；
  但 B/D 的 −3.7 ~ −5.4 已经超过单段噪声量级。
- 没有试「保留鼓的伴奏+贝斯」（Mitoma 的配置），也没有试逐轨增益扫描。
- 评测用的是 App 的完整段解码器与固定节拍网格；换解码器可能改变绝对值，
  但六个条件之间的相对关系应保持。

## 7. 复现

```
build_inputs.py   # 生成 A/B/C（D 在 diagnose.py 里）
level_match.py    # 响度对齐版本
run_inputs.py     # 冻结前端 + 完整段解码，产出 *.lab
score_inputs.py   # 帧级 / 段级 / 边界 F1
diff_analysis.py  # 改对 / 改错逐段统计
```
