# 音轨分离 · 第一版交付记录

日期：2026-11-01。方案与选型见 [PLAN.md](PLAN.md)。本文只记录**实际跑出来的**结果。

## 1. 做了什么

在 Chord Studio 里新增一条独立的产品线：**音轨分离**。它与和声识别并列，互不依赖。

| 层 | 内容 |
|---|---|
| 后端 | `app/web/stems_worker.py`（demucs 分离 + 逐轨标注 + 缓存）、`app/web/server.py` 新增 4 个接口、`app/web/jobs.py` 新增 `stems` 任务类型（不覆盖分析结果） |
| 前端 | 新页面 `/stems`：`stems.html` / `stems.js` / `stems.css`；工作台新增「音轨分离」按钮与「分轨视图 →」入口 |
| 数据 | `<data>/stems/<audio_sha>/`：4 个 mp3（播放）+ 4 个 wav（无损）+ `manifest.json` |

## 2. 实测

### 2.1 速度（CPU，htdemucs，8 线程给 demucs）

| 音频 | 耗时 | 备注 |
|---|---|---|
| 60 s 片段 | 24.3 s（RTF 0.40） | 含模型加载 |
| 《虚拟》238 s | **161.7 s** | 含解码、分离、mp3 转码、逐轨标注 |

第二次点击同一首歌直接命中缓存，3 s 内返回。

### 2.2 《虚拟》分离结果

| 轨道 | 电平 | 有声时间占比 | 首次–末次出现 | 谱质心 | 备注 |
|---|---:|---:|---|---:|---|
| 人声 | −21.6 dB | 72% | 00:16–03:58 | 3953 Hz（高频） | |
| 鼓 | −24.2 dB | 33% | 01:23–03:34 | 1482 Hz（中频） | 只在副歌出现，符合听感 |
| 贝斯 | −20.0 dB | 66% | 00:06–03:50 | 278 Hz（低频） | 低音主音 = C |
| 其他 | −18.5 dB | 97% | 00:01–03:54 | 935 Hz（中频） | 钢琴为主 |

BPM 130.43、126 小节，来自该项目已有的 `beats.json`（madmom 拍点），不是估计值。
四个 wav 时长完全一致（238.123 s），mp3 各 5.5 MB。

### 2.2b 《坏女孩》244 s（第二首，全流程走 UI）

| 阶段 | 耗时 |
|---|---:|
| 分离 | 146.2 s |
| 转码 | 9.2 s |
| 标注 | 1.1 s |
| **合计** | **约 157 s** |

## 3. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/projects/{id}/separate` | 提交分轨任务（`force` 可强制重算） |
| GET | `/api/projects/{id}/stems` | 读 manifest（未分轨返回 404） |
| GET | `/api/projects/{id}/stems/{file}` | mp3 内联播放 / wav 下载 |
| GET | `/stems?project=<id>` | 分轨页面 |

## 4. 已知限制

1. 模型固定为 `htdemucs`（4 轨）；钢琴/吉他合并在「其他」里，六轨模型质量不足未启用；
2. CPU 分离一首 4 分钟歌约 2.5 分钟，期间是后台任务，页面可关闭；
3. BPM 优先复用拍点分析；只做分轨、没做和声识别的项目会用 librosa 估计并标注「估计值」；
4. mp3 192 kbps 只用于试听，无损 wav 保留在缓存目录供下载；
5. 分离质量主观项需要人耳验收（本次未做听感评分）；
6. 分轨任务运行时项目列表显示「分析中」，实际是分轨任务（状态文案未细分）。

## 5. 过程中修掉的三个问题

| 问题 | 原因 | 修法 |
|---|---|---|
| 提交分轨后 `/api/jobs/{id}` 全部 404 | 插入新路由时把原来的 jobs 路由整段替换掉了 | 重新插入该路由 |
| 分离进度长时间停在 0% | demucs 的 tqdm 用 `\r` 刷新，按行读会阻塞 | 改成按字节块读、按 `\r`/`\n` 切分 |
| 工作台里主调判断选不到「连续评分」 | `desktop.js` 对 retained10 强制 `keyMode=madmom` 并禁用选择框 | 只禁用不支持的选项，默认保留连续评分 |

第 3 条是上一轮主调模式接入时的遗留缺陷：后端与 HTML 都支持连续评分，但桌面壳把它强制改回 CNN。
