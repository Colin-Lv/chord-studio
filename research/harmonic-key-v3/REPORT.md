## 使用入口与实际变化

刷新工作台、重新打开项目，在“局部调性与转调 · 和弦推理 v3”查看结果。切换和弦来源会切换对应调性时间线。点击时间定位试听，展开查看局部级数、和弦解释、竞争调性、短暂主音化与借用/短转调对照。

全曲摘要分别记录起始调、结束调、有效调区时长占优的调。上方单个主调是时长汇总，不表示全曲只有一个调，也不表示“开头一定是这个调”。人工全局调和原有小节级数设置保留；新面板内部级数采用各段局部调。人工改和弦不会暗中改写本次原始模型时间线。

新分析及分轨和弦发布后自动生成对应时间线。未补算的旧项目需重新分析。已有页面需要刷新以加载新脚本。

## 推理架构

1. 从每个模型和弦来源独立读取完整标签与时间。严格保留根音、三音、五音、七音、扩展音和斜杠低音；不把转位低音当成新根音。相邻同一和声合并，避免帧数冒充证据量。
2. 对 24 个大小调计算调内兼容、平行调借用、已解决次属和弦、未解释变化音、主和弦、属和弦、属到主、下属到主、前属到属与主音出发等特征。`F#:maj9` 包含 E♯，不能当作 B 大调的普通 V7。
3. 用受控符号和弦样例训练轻量候选排序器；运行时仅需 JSON 权重，不依赖训练库。用持续转调/短暂主音化配对和不转调反例选择连续解码的转调代价。
4. 在时间轴上作分段动态规划，先决定局部调区，再汇总全曲。允许关系、平行大小调转换。单独一个孤立和弦不能建立独立调区。极碎来源保留全部和弦观测，仅在小节/时间提议点附近限制边界搜索量。
5. 同时保留未拆分的变化和弦短段，对比继续原调、平行调借用、局部新调。解释中包含原调、局部前三候选、平行调及其关系调，因此可直接比较 G♯ 大调借用与短暂 B 大调解释。
6. 输出候选切点、首个“新调调内而旧调非调内”的和弦、首次属到主到达。三者不混为一个时刻；相邻和弦范围不是统计置信区间。

CNN 和旧连续评分保存在 `key_analysis_before_v3`，旧融合保存在 `key_fusion_before_v3`；它们不覆盖新时间线。每个来源绑定音频、运行、来源哈希和模型哈希。全局人工审阅文件不写入。无有效和弦区间不计入时长汇总，跨空白不计终止式。

关键文件：`app/harmonic_key_v3.py`、`app/web/harmonic_key.py`、`app/web/models/harmonic_key_v3.json`、`frontend/harmonic-key.js`。接入 retained worker、传统 worker、V2/V3.1 分轨发布流程。

## 当前真实歌曲结果：模型推断，不是人工真值

《使一颗心免于哀伤》，`retained10_full`：

| 调区 | 解码区间 | 可区分新旧调的首个和弦 |
|---|---|---|
| B 大调 | 00:05.80–00:47.81 | 起始调区 |
| G♯ 大调 | 00:47.81–01:14.82 | 00:50.82 D♯7；00:56.825 到 G♯ |
| B 大调 | 01:14.82–01:53.82 | 01:14.82 G♯m；01:16.315 Bmaj7 |
| G♯ 大调 | 01:53.82–03:17.95 | 01:56.83 D♯7 |

00:47.81 与 01:53.82 是解码器放置的准备区边界，不应把 Amaj9/Amaj7 直接说成“已经证明 G♯ 大调”。更清楚的变化音证据分别从 00:50.82、01:56.83 开始。当前第一段 G♯ 与 Fm 的竞争仍明显。

按有和弦证据的调区时长汇总，B 为 81.01 秒，G♯ 为 111.14 秒，所以摘要为 G♯、起始调为 B。末尾 03:17.95 之后该来源没有有效和弦覆盖，不推断尾奏调性。

02:26.805–02:32.805 的 `E → G♯m7 → B → F♯maj9` 单独展示竞争解释。当前长程路径继续 G♯；前三个和弦可作平行小调借用。最后的 F♯maj9 不完全符合 G♯ 小调或 B 大调，应先复核上游扩展音，再讨论短转调。没有将用户提出的 B 回归解释写成真值。

分轨 V3.1 来源的 00:56.825 附近把原来源 G♯ 主要改成了 Fm，导致首次转调区更偏 Fm；尾段也可能偏 C♯。来源差异确实会改变调性，不能宣称“分轨一定更准”。

《虚拟》，完整段来源：摘要 C；局部为 C（00:01.80–00:57.20）→ Am（00:57.20–02:22.12）→ C（02:22.12–03:52.62）。**其中 Am 解释仍未经过独立听辨确认，不能据此宣称歌曲真实转调。** 已避免把短暂 G♯ 和弦单独宣布成 G♯ 调。小节编号沿用当前应用网格，不自动修正之前发现的双倍小节问题。

两个项目的 `raw_madmom` 来源存在不符合时间轴校验的记录，面板明确显示不可用，未静默截断或重排原数据。其他来源继续可用。

## 训练与检查

训练数据：180 条受控符号序列；排序验证 40 条；候选转调代价同时参考 16 条验证序列与 10 条主音化/转调配对。随机移调、时值、乐句组合与起点，并加入借用、次属及主和弦占比较少的样例。包含关系大小调与平行大小调转调。最终权重和全部数据/分割在 `training_report.json`、`symbolic_data.json`、`train.py`。

测试生成种子与训练/验证不同，但使用同一套乐句模板，因此不是跨风格、独立真实录音的盲测：

- 全段候选排序与生成标签一致：40/40。
- 预设不转调序列，整条时间线路径一致：34/40；仍有 6 条过度分段或局部调性偏差。
- 配对控制路径一致：12/12，包括 6 条短暂主音化、6 条持续转调。
- 6 条持续转调中 4 条切点完全一致；2 条平行大小调转换晚一个和弦，不能仅因调名正确宣称边界全对。
- 新推理、和弦语义、分轨发布及传统 worker 集成回归：80 passed、13 subtests passed。
- 无浏览器的界面契约检查：来源切换、时间跳转、局部级数、不改变全局手动调、清除旧来源内容，通过。
- 安装版实际 Python 环境重新跑两首歌曲，和在线 API 返回的路径一致；首页和新脚本返回成功。见 `live_checks.json`。

扩展历史测试存在 9 个原有失败：旧 HTTP Range 行为、旧修订测试夹具缺少当前要求的音频身份、历史冻结音频缺失。将传统 worker 替换成 Git HEAD 的原实现后仍复现同样 9 项，见 `legacy-baseline-tests.log`。本次发现并修复了额外一个传统 worker 阶段回调参数错误，相关回归现已通过。没有为通过旧测试而放宽音频身份保护。

这次没有合成音频或训练声学和弦模型：排序器直接吃和弦符号，渲染 MIDI 再重新转录会引入另一层误差；真实声学模型仍为已有冻结模型。

## 本轮需要保留的错误记录

1. 首尾总为主和弦的训练样例会泄漏答案，夸大首尾位置作用。已随机旋转、按时长归一化首尾贡献。
2. 只检查全段选调正确，不能发现过度转调。必须同时测不转调路径、持续转调、短暂主音化和边界。
3. 对每段平均分独立归一化会改变不同切法的奖励，可能把变化和弦挪到不兼容区域来提高候选分差。已改为观测级归一化，比较不同分段时归一项保持一致。
4. 训练不合并重复和弦、推理合并，会使转移特征不一致。现在两端都合并。
5. 片段首部不能借用片段外的属到主到达，尾部不能借用片段外的次属解决。已隔离。
6. 单个 G♯ 和弦和 G♯ 调是不同结论；当前对孤立和弦保留局部竞争解释，不新建独立调区。
7. 已安装目录可能落后于工作区。实际运行检查发现旧 `chord_semantics_v3` 包导入问题，已同步现有的相对导入修复；语义规则未改变。
8. 用户建议的转调时间、曲谱、已见歌曲都不能悄悄变成训练真值。权重只拟合符号控制集，但本次架构迭代已经看过两首歌曲，因此真实结果只称开发回归。

## 研究依据与后续限制

- [Noland & Sandler，ISMIR 2006：基于和弦序列的 HMM 调性估计](https://archives.ismir.net/ismir2006/paper/000091.pdf)：参考和弦转移与时间上下文；本实现为可变时长分段 DP，不声称复现该论文性能。
- [DCML 标注标准](https://dcmlab.github.io/standards/build/html/reference/examples.html)：参考局部调、主音化及歧义表达；本实现输出机器候选，不自动视为已确认调性标注。
- [Modulation / tonicization 研究](https://napulen.github.io/publication/modulation_tonicization/)及[配套数据仓库](https://github.com/DDMAL/key_modulation_dataset)：局部调标签与真正转调不是同一个问题；此次未把该数据集宣称为已训练或测试数据。
- [FMP：HMM 和弦识别教程](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C5/C5S3_ChordRec_HMM.html)：参考序列观测、状态转移与解码原则。
- [Chordotomy 和声实现说明](https://github.com/zeikar/chordotomy/blob/main/docs/harmony.md)：作为工程参考入口，未引入其模型权重或声称复刻。

尚待改进：当前只使用获胜和弦标签，未传播和弦后验不确定性；独立旋律、低音旋律重心尚未接入消歧；短暂回归、关系大小调、缺主和弦循环依然困难。段落相似性只轻微影响边界，不把 A/B 相似段自动命名成主歌/副歌。应继续收集人工确认的局部调性与允许的边界范围，再做独立风格划分评估；不得拿当前两首开发歌曲的效果当泛化准确率。
