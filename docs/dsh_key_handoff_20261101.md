## 一、最需要纠正的旧结论

### 1. 《坏女孩》成功原因写错了

安装版 `web/retained_worker.py` 实际先执行 `guard_456`，再执行 `key_decision.decide`。冻结输入的可执行追踪是：和弦推断 C♯m → 456规则改为 E → 与 CNN 的 E 一致。`decide` 使用 layer 的 penalty，不使用 idiom/frame_bonus 决定胜负。

进一步把这两个加成字段在内存中改为 −999999，最终是否覆盖及原因均不改变。因此 `LAYERS_REPORT.md`、`FAILURE_ANALYSIS.md` 中“已经不依赖456规则，是大调进行加成压过小调模板”的因果说明不成立。诊断 JSON 里出现某字段，不代表该字段参与决策。

### 2. 有些所谓“音乐推理”并未实现相应含义

- 高频音级集合不能证明某个有序进行出现；相同集合可以有不同顺序和落点。
- `_inventory` 用字符串是否含 `min` 判断小调。同样的 F–G–Am，写 `Am` 时覆盖率0.667、保持 Am；写 `A:min` 时覆盖率1.0、改判 C。标签别名改变了音乐结论。
- `_cadences` 将 G–N–C 跨空白计为一次终止，也将 Gsus4–C 计入；它没有核对目标大小性质。不能据此断言歌曲有或没有正格终止。
- `force` 分支可绕开 coverage/margin 要求。惩罚一个候选不等于已经证明另一个候选正确。
- 研究侧 +1.20 大调奖励对应 POP909 总体87.57%→82.07%，不能仅突出大调子集提升，也不能将继续加门控当成已验证的补救。

这些生产侧问题在本轮**完成定位与反例留档，尚未修改安装版**。可执行反例：[legacy_probes.json](D:/ChordStudio/research/key-audit-20261031-r1/legacy_probes.json)。

### 3. 失败统计不能直接升级为音乐学结论

旧失败报告95例中，“主和弦时长<10%”实际22例，“<5%”实际9例；报告末尾却把22例写成<5%。42例没有被旧终止计数器检出终止，也不足以证明76个关系调错误大多是歌曲没有主音。

低主和弦占比、未检出传统 V–I、调外音较多，都只是当前特征的观测。它们可能涉及旋律、非传统调性、局部转调、错误和弦、解析损失或参考口径。未经独立听辨及结构核验，不能认定“人也无法判断”“参考错了”“规则不会错”。本轮旋律探针中的070号案例，就在旧主和弦占比为0时仍提供了偏向参考主音的旋律证据；它说明旧特征有遗漏，不足以单独裁定全曲。

## 二、评测口径的新发现

[POP909官方说明](https://github.com/music-x-lab/POP909-Dataset) 将 MELODY 定义为主旋律轨，key_audio.txt 定义为从原音频提取的局部调变化信息。它不是909份已独立人工裁定的全曲主调。

本地909首中152首的 key_audio.txt 含多个不同调标签。`app/import_pop909.py::parse_key` 取的是**单个最长片段的标签**，并非各调累计时长最多。180、843两个案例中这两种口径还会给出不同结果。即便改成累计时长最多，也不能自动等同于音乐上的全曲主调。

因此：旧909例数字可以保留为“对导入参考标签的一致率”，不能直接解释为全曲人工主调准确率；涉及多局部调的失败需先检查评价目标。本轮没有改参考标签，没有用这一发现免除算法错误。

现有147例以小调为主（131小调、16大调），已多轮查看和调参；`harmonic_new_sealed` 只是历史名称，不再是盲测。两份《虚拟》属于同一作品的版本回归，不是两首独立歌曲。旧模型在这批数据输给另一模型，也不足以推出“换模型不能改善”。

## 三、已完成的具体修正

修改 [key_coherence.py](D:/ChordStudio/Dialogue/app/key_coherence.py)：

1. 在计算上下文前合并相邻、和声构成相同的持续片段，保持空白间隔，不修改输入。旧代码对 E7两秒→Am两秒，在 C 下的分数为−0.4315；仅将 E7 切成两个一秒片段便降至−1.8060。原因是只有最后一段被解释为已解决的副属。新增测试比较全部24个候选的总分，而不仅是回归次数。
2. 普通属/副属支持要求大三度、纯五度和无七音或小七度，解决目标须有大/小三和弦结构。Emaj7→Am 不再被标成普通副属解决。变音属和弦等复杂情况仍需单独建模，不能声称已覆盖。
3. 拒绝非有限、负起点、非正时长、乱序重叠的片段；音频通道要求24个唯一有效调标签、有限非负分数及正总和。缺少音频时可完全省略该通道，不把残缺候选列表伪装成完整分布。
4. 改正注释：加权调外音占比只是诊断项；当前和声解释仍按完整和弦分类，并未实现“扩展音不确定性”的概率处理。

修改 [回放入口](D:/ChordStudio/Dialogue/app/evaluate_key_coherence.py)，新增 [冻结与比较工具](D:/ChordStudio/Dialogue/app/audit_key_revision.py)：每次使用新目录，冻结147例及3个项目来源、实际run、输入哈希、解析器与裁决代码；校验哈希后回放，拒绝覆盖已有比较结果。明确第三个项目取 `v1`，不再静默退回第一个来源。历史v4文件保持不变。

13项测试通过，覆盖移调、持续和弦切分、间隔、和弦品质、异常输入和旋律探针语义。新增测试在修复前确实检出缺陷，失败日志保存在 [tests_before.txt](D:/ChordStudio/research/key-audit-20261031-r1/tests_before.txt)。

## 六、dsh 的下一轮执行顺序

1. **先复现，不继续调阈值。** 阅读错误集合，运行13项测试；对冻结输入重放，应得到本报告的逐曲结果。保留旧实验与失败例。
2. **修复生产语义问题的独立分支。** 小调性质用解析后的三音/五音；终止必须检查连续性、双方品质及明确的功能定义。先做反例测试与全量回放，再讨论是否去掉456规则。不要用另一层强制/否决来修补前一层。
3. **先建立可信的句级诊断材料。** 从已有失败与正常样本中同时取例，人工标记旋律乐句边界、长音、休止、低音走向、局部调与重复段；已看过的样本只作诊断。优先包括070、064、067、143及两个147例退步，避免只挑成功故事。音频与MIDI/曲谱需确认版本及时间对应。
4. **检验同和弦、不同旋律落点的反事实。** 移调全部声部结果应随之移调；仅切碎同一和弦不改变结论；仅更换转位不自动改变主音；休止前音不是主音的真实例子必须纳入。比较长音、旋律走向、回归、低音等各项增量，保留负结果。
5. **再做真实音频声部提取与24候选融合。** 不把全频谱低频能量当成已识别的低音声部，不把根音等同主音。先验证声部/音符提取质量，再讨论连续证据融合，避免分类器错误与音符错误相互放大。
6. **验收需按作品隔离的新数据。** 同曲不同版本放同组；单调与转调分开报告；明确局部调/全曲主调参考；报告总体、大小调、错误类型和逐曲收益/退步。保留《虚拟》C的必要回归要求，但不能只凭它通过即上线。预先固定参数及评价口径后再看新集。

当前实验模块可继续研究；尚不足以替换生产默认。这个判断来自仍存在的退步、未校准权重和缺少独立新集，不是认为《虚拟》的C与泛化天然不可兼得。
