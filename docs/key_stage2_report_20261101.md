## 1. 实现修复

[key_transition_semantics.py](D:/ChordStudio/Dialogue/app/key_transition_semantics.py) 提供统一的和弦性质与相邻回归判定，并接入独立副本中的 `key_decision.py`、`key_layers.py`：

- 用解析后的三音与五音区分大、小、减、增和弦；挂留和弦和无三音和弦不默认为大和弦。Am、A:min等别名给出相同证据。
- 普通V(7)→I/i核对时间连续性、属和弦大三度/纯五度/七音性质，以及目标和弦的大小性质。G–N–C不再跨空白计数，Gsus4–C、Gmaj7–C也不冒充常规属到主证据。
- 转位保留根音含义，但这里只称“相邻和声回归”，不声称是根位终止或乐句终止。
- 对诊断字段明确标注“无序和弦库存”“相邻和声”，不把库存匹配叫作已经检出的有序进行。
- 暴露实际生效的coverage_ok、veto、force字段，便于追踪因果。修复了未在主调用链使用的 `adjust` 接口参数数量错误，并补测该接口。

没有修改现有权重和阈值，也没有把新特征接入主调实验原型。456规则和强制覆盖保留在副本中只为做对照，不代表认可其音乐学有效性。

## 3. 实际接入人工结构材料

找到并下载了研究者公开的 [hierarchical-structure-analysis](https://github.com/Dsqvival/hierarchical-structure-analysis) 中8首歌曲的两份人工结构标注、量化旋律及和弦材料，固定提交为 `3a8d0d096e8dd2f62e38e48500bf0b230eeca585`，保留来源、许可证和文件哈希。依据论文，这些标记描述重复结构中的乐句，**不是终止式标签或主调标签**。[论文](https://www.cs.cmu.edu/afs/cs/Web/People/rbd/papers/dai-mume2020.pdf)

选择既有失败064、067、070、143，以及预先确定的对照001、002、005、006；没有按新实验是否成功挑选。两份人工标注分别保存，不挑有利的一份。

上游明确提醒，其预处理会改变原MIDI的小节起点。本轮通过音高序列匹配、MIDI tick和中位偏移核验对齐：7/8首通过“至少95%音符匹配、95分位时间残差不超过一个十六分音符”的数据映射检查。005残差达8个十六分音符，说明存在内部位置差异，**未给它附加原MIDI时间或钢琴低音代理**。这项检查用于防止错配数据，不参与主调裁决。

另外，原MIDI里出现1/4、2/4等与研究标注小节单位不一致的元数据。本轮按上游结构分析代码明确的小节单位解析，而非直接套用原MIDI拍号。所选8首在该结构数据中均为每小节16个十六分音符。

## 4. 结构材料得到的诊断结果

将人工标注中旋律乐句的末个音、其前音走向、音长、休止距离、同时刻和弦保留下来。跨越边界的持续音不计作已结束的音；文件尾部未编码的空白不当作已观察到的休止。对齐通过时附上原MIDI中PIANO轨的最低同时发声音，但它只是**钢琴最低音代理，不是已经分离并确认的低音声部**。

以下仅比较参考与关系调这两个已知候选的“末音命中主音次数”，不构成24调分类器：

|---|---|---:|---:|
| 001 | F♯ / D♯m | 4 / 0 | 4 / 0 |
| 002 | B / G♯m | 2 / 0 | 2 / 0 |
| 005 | G / Em | 1 / 1 | 1 / 1 |
| 006 | Cm / E♭ | 4 / 0 | 3 / 0 |

## 5. 两个真实录音退步的具体来源

原音频已从归档中找到，SHA-256均与原始和弦缓存记录一致。已生成可听片段与原时间范围，但本轮没有完成独立听审或音符转录，以下只定位计算路径：

**191347，参考D♯m，原型A♯m。** CNN声学项明显支持D♯m（−0.5014对−1.2861）；但A♯m获得10次前属到主相邻回归，封顶后加0.8，D♯m该项为0。和声项整体翻转排序，最终A♯m仅领先约0.0502。回归频率不等于结构落点；其中G♯大和弦在D♯m下被解释为借用，但没有进入当前“原生调内前属回归”计数。这暴露了该项对调式借用与重复循环的局限，不足以证明D♯m有误。

**853834，参考Em，原型E。** 原始约120秒的LAB只有E大三和弦与N；有和弦标签的片段共82.4秒。原型内部对这些可解析片段归一化，所以E的主和弦占比是1.0，**并不是整段录音100%都已确认E和弦**。CNN声学项支持Em（−0.1247对−2.2510），但硬和弦标签产生的和声差异仍使E获胜。应该检查三音的真实音高及和弦后验，而不是凭top-1标签强制证明大调。

完整候选、片段和来源：[recording-packet/packet.json](D:/ChordStudio/research/key-stage2-20261101/recording-packet/packet.json)。

## 6. 新发现的解析缺口

本轮还确认原解析器将 `Cmaj9` 展开成C–E–G–B、`Dm9`展开成D–F–A–C，遗漏显式九音；`G#add9`直接解析失败。与此前“完整和弦音”的表述相比，这意味着当时诊断实际只覆盖了解析器保留的音。证据：[parser_followup.json](D:/ChordStudio/research/key-stage2-20261101/parser_followup.json)。

本轮没有把解析器改动混入已经冻结的语义消融，否则会无法区分结果由哪项改动造成。该问题已列为下一步第一项；修复应使用独立对照，保留扩展音、斜线低音、未知后缀状态，并重新检查《虚拟》的和声解释。

## 7. 下一步与验收条件

1. **先修和弦解析完整性，再谈音级冲突。** 建立9、add9、转位与等音标签的完整音集合反例；单独回放新旧解析器。不得把缺失音解释为歌曲没有该音。
2. **补两个退步的音符证据。** 853834优先检查G/G♯三音与真实声部来源；191347区分循环内部的连接与段落终止，保留借用和弦的回归关系。先校验提取质量，再进入连续评分。
3. **结构作为上下文，不做简单“末音=主音”。** 两种人工标注的冲突保留；分别观察句中、句末、段末，以及重复段末音/低音的一致性。外部人工标注只作研究诊断，不能在普通用户歌曲推断时假装可得。
4. **拒绝把旧规则的退步修补成更多门控。** 本轮支持重新设计统一证据融合，未证明任何一种旧门控组合足够好。连续评分原型也仍有重复计数和硬标签可靠性问题。
5. **生产替换需新作品验证。** 《虚拟》C与《坏女孩》E仍是必要回归项；还需独立作品集和逐例收益/退步记录，不能只凭本轮已暴露资料上线。
